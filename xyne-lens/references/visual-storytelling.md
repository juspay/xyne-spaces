# Visual storytelling

Use a short arc rather than a list of animated slides:

1. **Hook** — show a concrete puzzle, input, or misconception.
2. **Vocabulary** — introduce only the objects required to reason about it.
3. **Mechanism** — animate the transformation, flow, geometry, or state change.
4. **Insight** — connect the visible change to the supported claim.
5. **Takeaway** — leave one concise conclusion on screen.

For each beat, decide its purpose, visible objects, motion, supported claim, and transition. Preserve one object or visual metaphor through multiple beats whenever possible.

## Directing rules

- Show before naming. Let an object move, split, align, or transform before showing its formula or label.
- Transform a diagram into the next abstraction instead of replacing it with a new slide.
- Pause briefly after the key transformation. Constant motion weakens emphasis.
- For a system, show a small request/state/data-flow model rather than source code.
- For an algorithm, let a single highlighted transition answer “what changed and why?”
- End a beat with resolution; the next beat should answer the visual question just raised.

Avoid invented visual detail. A simplification is good when it preserves the claim and makes the causal relationship easier to see.

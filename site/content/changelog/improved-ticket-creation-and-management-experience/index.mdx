Ticket workflows in Xyne Spaces are now more structured and easier to operate end-to-end—from creating tickets to tracking progress and managing views. Tickets can be created directly from **linked channel conversations** by converting a message into a ticket, or created manually from the **Tickets tab**. In the conversation-based flow, Xyne suggests a ticket title from the discussion context, and in both flows Xyne runs **duplicate detection** to prevent repeated work and reduce noise in the system. Once created, tickets remain visible in both the Tickets tab and the originating chat for shared context and transparency.

Ticket execution is supported with **smart assignment** using **User Groups**, where roles like assignee, PR reviewer, and QA can be auto-assigned based on admin-managed configurations. Inside the ticket, all work context is consolidated: status and key metadata are surfaced at the top, the original conversation remains preserved below, and ongoing discussion continues in the same thread. A dedicated **activity feed** logs changes such as status updates, assignment changes, and priority shifts to keep everyone aligned as the ticket evolves.

For teams with structured delivery workflows, ticket management now supports review-driven processes like **maker–checker**, along with **Bitbucket pull request tracking** directly within the ticket for clear development visibility. Managing tickets across boards is also smoother with board switching, consistent organization via **status categories**, and flexible views like **Kanban** for workflow tracking and **List** for audits and detailed reviews—supported by filters for assignee, priority, and board to help teams stay focused.
